## Что такое JobForge

JobForge = движок career-ops (оценка A–F, подгонка резюме/писем, PDF, трекер)
+ **несколько переключаемых источников поиска под разные цели** + хьюманайзер.
Идея: источник = цель. Разным людям нужны разные «пруды».

---

## Рабочий процесс JobForge (5 шагов — всегда веди человека по ним)

1. **Профиль/резюме** — онбординг: вставить резюме / LinkedIn / интервью → `cv.md`,
   `config/profile.yml`, архетипы. (Делается один раз.)
2. **Опрос про поиск** — что за работа, тип занятости, удалёнка/на месте, локация →
   сохраняется в `config/profile.yml > search_prefs`. (Один раз; дальше помним.)
3. **Поиск + оценка** — `/find` ищет по всем каналам → `/career-ops pipeline`
   оценивает A–F под резюме и отсеивает не подходящее.
4. **Выбор (важно!)** — покажи человеку шортлист с баллами; он **сам отмечает**,
   на какие откликаться. `/prep` делаем ТОЛЬКО для выбранных (под каждую — своё
   резюме, это затратно — не на все 200).
5. **Отклик** — `/prep` готовит пакеты (уникальное резюме + письмо + шпаргалка),
   человек подаёт **сам** (формы не заполняем).

Где человек сейчас — ориентируйся по наличию файлов: нет `cv.md` → шаг 1;
нет `search_prefs` → шаг 2; и т.д.

## Мастер настройки → команда `/setup`

Шаги 1–2 (профиль/резюме + опрос про поиск) ведёт дружелюбный русский мастер —
команда **`/setup`** (`.claude/commands/setup.md`). Когда пользователь говорит
«настрой JobForge», «setup», «помоги настроиться», ИЛИ при первом запуске нет
`cv.md` — запускай `/setup`, а НЕ английский First Run из CLAUDE.md.

`/setup` собирает `cv.md`, `config/profile.yml` (+ `search_prefs`), `modes/_profile.md`,
а дальше человек идёт по рабочему процессу: `/find` → оценка → выбор → `/prep`.

## Быстрый сценарий: одна вакансия (без поиска)

Если пользователь **кидает одну вакансию** (ссылку или текст) и просит «оцени» /
«разберись» / «подготовь отклик»:
0. **Если дана ссылка** — открой её (WebFetch). Не открылась (защита/JS)? Попробуй
   стелс-фетч: `./.venv/bin/python sources/fetch_page.py "<url>"`. Если и так текста
   мало — попроси скопировать текст вакансии вручную.
1. **Оцени** её под резюме (A–F: совпадения, гэпы, красные флаги) и покажи кратко.
2. По согласию — запусти **`/prep`** на эту вакансию (резюме под неё + письмо через
   humanizer + шпаргалка ответов). Без авто-заполнения форм, подаёт сам.

Это работает и без `/find` — самый быстрый путь, если вакансия уже найдена где-то ещё.

## Поиск вакансий — единый вход

**Всегда веди поиск через команду `/find`** (`.claude/commands/find.md`) — она
спрашивает режим (🌍 везде / 🎯 под цель / ⚡ по профилю) и сама запускает нужные
источники. Когда пользователь говорит «найди вакансии», «поиск работы» и т.п. —
запускай `/find`, не дёргай скрипты по отдельности.

## Поисковый профиль (для запросов «по резюме»)

Описывай человека ЕГО словами (как в резюме). НЕ инфлейть в громкие роли вроде
«AI Engineer», если человек сам себя так не называет.

**Ключевые слова** для поиска бери из `config/profile.yml > search_prefs.keywords`
(их заполняет `/setup` из резюме — короткие реальные слова-навыки, не названия ролей).

**Приоритет каналов** (общий ориентир — подстраивай под цели человека):
1. **Фриланс** (Freelancer.com) — проектная/контрактная работа
2. **Стартапы** (Wellfound, YC) — builder/founding/generalist
3. **Общие remote-борды** (Remotive/RemoteOK/WeWorkRemotely/Working Nomads)
4. **JobSpy** (Indeed/LinkedIn) — корпоративные роли

Для junior/проектной работы выше ставь фриланс + стартапы; для опытных под штат —
компании/JobSpy. Corporate Indeed часто даёт generic «Software Engineer» — учитывай.

**Уровень:** junior-mid, builder/generalist, дружелюбно к contract/проектам.

## Источники поиска (детали; вызываются из /find)

### JobSpy — широкий пруд (международный)
Запуск через venv проекта:
```bash
./.venv/bin/python sources/jobspy_search.py "<запрос 1>" "<запрос 2>" --remote --location "Remote"
```
Площадки: indeed, google, glassdoor, zip_recruiter (можно добавить linkedin).
Параметры: `--results N`, `--hours-old N`, `--country`, `--dry-run`.
⚠️ Некоторые площадки могут блокировать серверные IP — запускать с машины пользователя.

### hh.ru — РФ-удалёнка
```bash
node hh-search.mjs "<запрос на русском>" --period 14
```
⚠️ hh.ru блокирует серверные/зарубежные IP → запускать с домашнего компа,
ВЫКЛЮЧИВ VPN (или с VPN на Россию). Международные источники — наоборот, можно с VPN.

## 🔴 Хьюманайзер — ОБЯЗАТЕЛЬНЫЙ финальный шаг (никогда не пропускать)

**ЖЁСТКОЕ ПРАВИЛО.** Любой сгенерированный для пользователя текст (сопроводительное
письмо, summary резюме) НЕ СЧИТАЕТСЯ ГОТОВЫМ, пока не прогнан через скилл
`.claude/skills/humanizer/SKILL.md`. Это касается **любого способа генерации** —
`/prep`, встроенного режима career-ops `cover`, ручного запроса «напиши письмо» и т.д.

Алгоритм (всегда):
1. Сгенерируй черновик письма.
2. **Прогони через humanizer** (вызови `/humanizer` или применяй паттерны из его SKILL.md).
3. Только ПОСЛЕ этого показывай/сохраняй результат. Версия на диске и для пользователя —
   уже очищенная.

Объём:
- **Сопроводительное письмо** — целиком.
- **Резюме** — только вступительный абзац (summary); буллеты опыта/навыков НЕ трогать
  (там ключевые слова для ATS).

Правила: менять только стиль, не факты. Сначала `voice-dna.md` (манера пользователя),
потом humanizer. Учитывать язык (EN/RU).

**Самопроверка перед показом письма:** если не прогнал через humanizer — вернись и прогони.
Никогда не отдавай «сырое» письмо.

## Отклики — только подготовка материалов (НЕ авто-заполнение)

Пользователь заполняет и отправляет формы **сам**. Когда он говорит «откликнись»,
«подготовь отклик», «apply» — запускай **`/prep`**, НЕ режим браузерного
авто-заполнения career-ops (`apply`/Greenhouse/Lever/Workday).

`/prep` готовит на **КАЖДУЮ вакансию отдельный** пакет: уникальное резюме под
эту вакансию (не одно на всех!), сопроводительное письмо (через humanizer) и
шпаргалку ответов на типовые вопросы форм. Дальше пользователь подаёт сам.

## Off-Limits
- **Никогда не заполнять и не отправлять веб-формы откликов** — только готовить материалы.
- Резюме под каждую вакансию — РАЗНОЕ, переакцентированное под её требования.
- Не редактировать системные файлы для персонализации — только пользовательский слой.
